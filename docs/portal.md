# Portal

The portal is the ticket list for the projects you belong to. An administrator adds you to a project.

## Switching project

The header lists the projects you can open. Administrators see every project. Everyone else sees projects they are a member of.

## Views

The view tabs change with your project role.

| View           | Who      | Shows                               |
| -------------- | -------- | ----------------------------------- |
| All            | everyone | Every ticket in the project         |
| Open           | everyone | New, In progress, and With reporter |
| Closed         | everyone | Done                                |
| To handle      | staff    | New and In progress                 |
| Unassigned     | staff    | Tickets with no assignee            |
| Awaiting reply | clients  | With reporter                       |

## Filters

Search looks at the title, the ticket number, and the reporter. Type, status, priority, and tag narrow the list further. The tag choices are the tags already used in that project. **Only mine** keeps tickets you reported, are assigned to, or watch. You can sort by last activity, by creation date, or by priority.

The header lists **active** projects. Enable a project in Administration to show it in the portal again. Its tickets stay in the database.

## Creating a ticket

**Create ticket** asks for a title, type, priority, and description. The description is Markdown. The new ticket starts as **New**, and you are the reporter. Inside a project the numbers start at 1.

Types: Bug, Question, Change, New feature. Priorities: Low, Normal, High.
